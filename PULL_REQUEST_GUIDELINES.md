# Pull Request Guidelines

Use these guidelines for every Dietum pull request.

## Scope

- Keep each PR focused on one issue or one tightly related slice of work.
- Do not combine unrelated cleanup with feature work unless it is required for correctness.
- Match the issue's acceptance criteria before requesting review.

## Before Opening A PR

- Run the relevant tests.
- Update `HANDOFF.md`.
- Confirm the branch name and commit message are descriptive.
- Verify any new UI states, empty states, and error states.

## PR Description Should Include

- Issue number and title
- Short summary of the change
- Files or areas touched
- Tests run and results
- Known gaps or follow-up work
- Screenshots or screen recordings for UI changes when relevant

## Review Expectations

- Call out any architectural decision that affects future work.
- Mention if the change introduces a new dependency or ownership boundary.
- Highlight anything that remains intentionally unfinished.
